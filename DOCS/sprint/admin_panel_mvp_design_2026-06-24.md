# Рабочая административная панель: дизайн MVP

Дата: 2026-06-24

## Цель

Привести существующую административную панель NEMI Translator к демонстрационно готовому состоянию: администратор входит по учетной записи, наблюдает реальные комнаты и активный ML-профиль, открывает поток комнаты и управляет ее жизненным циклом. Панель должна использовать backend API и WebSocket, а не `mockAdminRooms.ts`.

## Границы MVP

В объем входят:

- авторизация администратора через `POST /admin/login` и JWT-защищенные маршруты;
- список реальных комнат, общая статистика и состояние STT/MT/TTS;
- автоматическое обновление dashboard каждые две секунды;
- поиск по ID комнаты и фильтр по статусу;
- остановка комнаты из списка;
- детали комнаты с реальными REST-данными, транскрипцией и переводом через WebSocket;
- действия Stop, Reset listeners и Restart с подтверждением и защитой от повторного запуска;
- понятные loading, empty, success, API error и WebSocket error состояния;
- frontend build, backend smoke и автоматизированная браузерная проверка admin-сценария.

В объем не входят постоянная БД, история завершенных процессов после перезапуска backend, журнал последних 20 событий и отключение отдельного слушателя. Эти функции требуют расширения модели данных и API и не нужны для минимальной демонстрации требований ВКР.

## Архитектура

Существующее разделение сохраняется:

- `AdminLogin.tsx` отвечает только за форму входа и переход в панель;
- `adminAuth.ts` хранит и очищает JWT;
- `adminApi.ts` является единственной REST-границей административного frontend;
- `AdminView.tsx` отображает dashboard и экран комнаты;
- `RealtimeClient` получает события комнаты по каноническому контракту;
- `backend/app/api/http.py` предоставляет авторизацию, чтение комнат, системный статус и управляющие операции;
- in-memory store остается источником актуального состояния MVP.

Новые realtime-события и endpoints не вводятся. Legacy-файл `mockAdminRooms.ts` не используется рабочей панелью и может остаться справочным до отдельной очистки legacy-кода.

## Авторизация и ошибки API

Frontend передает JWT в `Authorization: Bearer` для всех admin-запросов. При ответе 401 или 403 токен удаляется, а интерфейс возвращает пользователя на `/admin/login`. Ошибки backend преобразуются в пользовательские сообщения; сетевые ошибки не маскируются сообщением «комната не найдена».

Поля входа имеют подписи, состояния фокуса и корректные атрибуты автозаполнения. Во время запроса повторная отправка формы блокируется.

## Dashboard

Dashboard загружает список комнат и системный статус независимо, чтобы временная ошибка одного запроса не скрывала успешные данные другого. После первой загрузки комнаты обновляются каждые две секунды без полноэкранного loading-состояния. Ручной Refresh остается доступным.

Строка комнаты показывает ID, языки, статус, слушателей, задержку и действия. Кнопка Stop вызывает реальный endpoint только после подтверждения. Пока действие выполняется, соответствующая кнопка отключена. После завершения список и агрегированная статистика обновляются.

## Детали комнаты

Экран сначала получает REST-снимок комнаты, затем подключается к WebSocket с ролью `admin`. События `room:status`, `room:listenerCount`, `stream:transcription` и `stream:translation` обновляют интерфейс без перезагрузки.

Управляющие действия требуют подтверждения и выполняются по одному. После ответа backend REST-снимок перечитывается. Ошибка действия отображается отдельно от успешного результата. При размонтировании компонента таймеры и WebSocket освобождаются.

## Доступность и визуальный стиль

Сохраняется существующий темный кинематографичный интерфейс и Tailwind-паттерны проекта. Интерактивные элементы получают видимый focus state; кнопки имеют понятный текст или `aria-label`; сообщения об операции объявляются через live region. Панель остается пригодной для ноутбука и планшета.

## Проверка

Минимальная приемка:

1. Без JWT маршрут `/admin` переводит на `/admin/login`.
2. `admin/admin` в dev-профиле открывает dashboard.
3. Созданная через backend комната появляется в dashboard без перезагрузки страницы.
4. Поиск и фильтр работают по реальным данным.
5. Stop из dashboard переводит комнату в `stopped`.
6. Details показывает REST-состояние и получает realtime-события.
7. Reset listeners удаляет только слушателей.
8. Restart переводит комнату в `connecting`.
9. Logout очищает JWT.
10. Frontend build и backend smoke проходят.
11. Browser-smoke проходит полный административный сценарий на запущенном Docker Compose.

## Стратегия реализации и коммитов

Работа выполняется небольшими проверяемыми шагами. Каждый завершенный шаг оформляется отдельным осмысленным Git-коммитом: спецификация, тестовый каркас, auth, dashboard polling, dashboard actions, room details, browser smoke и итоговая документация. В коммиты не включаются сторонние файлы `outputs/` и `.current_presentation_workspace`.
